# Case 04：OS 内存「负载爬升」≠「泄漏」—— R² 门控与稳态读取

对应章节 §11.3.2 内存维度（泄漏 4 条件：`trendDirection=up && R²>=0.7 && mean>=60% && slope>=0.5%/h`）。
用同一台宿主机（Docker VM）在不同时刻的实测数据，说明**斜率方向与 R² 门控**如何区分"压测爬升"和"泄漏"。

## 实测数据点（node-exporter 10.0.0.5:9100，analyze.py 各窗口）

| 时刻 | 窗口 | 使用率均值 | slope | R² | 判定 |
|------|------|-----------|-------|-----|------|
| 压测上升期 | 8min（高并发后） | 86% | +50.99%/h | 0.64 | **NONE**（R²<0.7 被门控拦下） |
| 压测上升期 | 6min（流量中） | 81% | +58.75%/h | 0.59 | **NONE**（R²<0.7） |
| 稳态（停流量后） | 6min | 81% | -89.12%/h | 0.18 | **NONE**（slope 为负） |
| 稳态（更久后） | 18min | 82% | -40.93%/h | 0.26 | **NONE**（slope 为负） |

## 读法

1. **Docker VM 的内存爬升（45%→86%）是负载不是泄漏**：压测时 slope 为正、R²≈0.6，
   未达到 `R²>=0.7`，泄漏 4 条件不成立 → 引擎正确判 NONE，没有误报。
2. **停流量后 slope 由正转负**（+50%/h → -41%/h）：内存会自己回落，进一步证明是负载。
3. **经验法则（写进 §11.3.2）**：OS 实证层要在**无流量/稳态**下读；若在持续爬升窗口
   （长时间单调上升）R² 达标误报 HIGH，处置是等稳态重跑，而不是采信泄漏结论。

## 复现

```bash
# 压测后立刻分析（上升期）
CONCURRENCY=6 ROUNDS=3 bash scripts/generate-traffic.sh
MINUTES=6 bash scripts/run-analysis.sh        # 看内存行 slope 为正、R²~0.6、NONE

# 停流量 4 分钟后分析（稳态）
sleep 300
MINUTES=6 bash scripts/run-analysis.sh        # slope 转负、NONE
```

> 判断泄漏一定看**斜率方向 + R² + 是否持续**，单个使用率数字（如 86%）不能定罪。
